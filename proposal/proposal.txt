Final Project Proposal

Project Overview:
	I plan to make an application that lets a user easily query an astronomy database to find information about objects in the sky on any given night. The goal of this project is to make observational data more accessible and convenient for amateur astronomers or anyone else interested in space. There are many astronomy databases with their own query applications, but they are not user friendly, even to those knowledgeable about astronomy. The target users are amateur astronomers, students, and hobbyists who want a quick, visual way to answer "what can I see tonight?" without learning a specialized query language.

Key Features:
	Observation planner – Allows the user to select a date and location for observing and plan out what they are going to observe. JavaScript will fetch matching objects from the deep-sky-objects API, filter them by visibility for the chosen date/location, and render the results as a dynamic, sortable list without reloading the page. CSS will lay the results out in a responsive grid/card layout so the plan is easy to scan, with hover and focus states that make each card feel clickable.

	Object details summary – Display attributes of the object relevant to observing (apparent magnitude, angular size, position in the sky, rise and set times, etc.). Clicking an object in the list triggers a JavaScript event handler that pulls the full record and injects it into a detail panel via DOM manipulation, calculating rise/set times client-side from the object's coordinates and the selected location. CSS transitions/animations will slide or fade the panel into view so switching between objects feels smooth rather than jarring.

	Object search – Search a specific object with their location to see if the object is visible, or when it will next be visible. A search input will drive an event-driven filter/query against the API as the user types or submits, and JavaScript will compute the next visibility window for that object. CSS will provide clear visual feedback (loading state, "not found" state, highlighted match) so the user always knows the state of their search.

	Saved/favorite objects – Users can save objects of interest to a personal watchlist that persists between visits using LocalStorage, so a returning user doesn't have to re-search objects they cared about before. CSS will style saved items distinctly (e.g., a filled star icon, accent border) so they're visually distinguishable from the general results.

Technologies Used:
	JavaScript concepts:
	- Variables, data types, and control flow: 
        parsing date/coordinate input, branching logic for visibility calculations (e.g., is an object above the horizon, is it currently nighttime).

	- Functions and objects: 
        reusable functions for coordinate math (RA/Dec to alt/az), API querying, and rendering; objects to represent an "observation session" (date, location, list of targets).

	- Object-Oriented Programming: 
        a class-based model (e.g., a CelestialObject class wrapping each API record with methods like isVisibleAt(location, time) and getNextRiseTime()) to keep visibility logic organized and reusable across features.

	- DOM manipulation and event handling: 
        dynamically building result lists and detail panels, handling clicks/input events for search, date pickers, and the save/favorite buttons.

	- API calls and asynchronous JavaScript: 
        fetch() calls to the Explore API (https://www.datastro.eu/api/explore/v2.1/catalog/datasets/deep-sky-objects/records) using promises/async-await, with loading and error states surfaced to the user.
        
	- LocalStorage: 
        persisting the user's saved/favorite objects and last-used location between sessions.

	CSS's role: CSS will be responsible for making the interface feel like a cohesive, modern app rather than a raw data dump — a responsive layout (grid/flexbox) that works on both desktop and mobile, a clear visual hierarchy between the search/planner controls and the results, smooth transitions when panels open or lists update, and distinct states for interactive elements (hover, focus, saved, loading, error) so the app is usable without reading labels.

Wireframe / UI Sketch:
	Planned layout (single-page app):
	- Header: app title + a persistent search bar and date/location controls.
	- Left/main column: scrollable grid of object cards (name/catalog ID, type, magnitude) from the current query.
	- Right/detail panel (or modal on mobile): opens when a card is selected, showing full object details and rise/set times, with a save/favorite button.
	- Sidebar or "Saved Objects" tab: list of favorited objects pulled from LocalStorage.
	A rough sketch will be added once initial layout is drafted in CSS.
